# ZDSM 紫微动态系统分析 Skill v1.0

## 0. Skill 目标

把紫微斗数从“星曜断语堆叠”转化为一套可重复执行的系统分析流程。

核心原则：

> 领域 Domain × 功能 Function × 状态 State × 交互 Interaction × 拓扑 Topology × 流向 Flow × 时间 Time × 现实环境 Context → 现实输出

本 Skill **不负责排盘**。  
排盘由上游 Chart Engine 完成，本 Skill 只接收结构化命盘并解释。

这样可以避免：
- 排盘流派差异污染解释逻辑；
- 四化表、流月流日算法被解释层自行猜测；
- 文墨天机、其他排盘器之间难以替换。

---

## 1. 强制口径锁定

每次分析开始前必须读取 `conventions`。

至少确认：

- chart_school：如 `sanhe_tianpan`
- chart_source：如 `wenmo_tianji`
- sihua_table_id：四化表版本
- self_transform_semantics：自化定义
- decade_method
- annual_method
- minor_limit_method
- monthly_method
- daily_method
- hourly_method
- true_solar_time_used

如果任一短周期算法未提供：
- 不得自行猜算法；
- 跳过该层；
- 在结果中写 `not_computed_due_to_missing_convention`。

---

## 2. 证据标签

每条规则必须注明来源类别：

- `T` = Traditional：传统结构/来源文献明确支持
- `S` = School-specific：特定流派方法，例如宫干飞化、自化
- `M` = Modern-model：ZDSM 系统化重构
- `E` = Empirical：现代实证或一般系统/心理研究支持

禁止把 `M` 或 `S` 写成“古籍原意”。

---

## 3. 读取层级

严格按顺序：

### Layer 1 — Skeleton / 骨架
读取：
- 命宫
- 身宫
- 十四主星
- 命财官迁
- 福德
- 生年四化

目标：
- 这个人的系统基本怎么运转？

### Layer 2 — State / 状态
加入：
- 庙旺陷平
- 双主星/同宫主星组合
- 主星之间的交互算子

目标：
- 哪些功能强、稳、难控制？

### Layer 3 — Topology / 传统结构网络
加入：
- 本宫
- 对宫
- 三方四正
- 必要时夹宫/空宫规则

目标：
- 哪些模块必须联读？

### Layer 4 — Support & Friction / 资源与摩擦
加入：
- 左右
- 昌曲
- 魁钺
- 禄存
- 羊陀
- 火铃
- 空劫
- 其他高权重辅煞

目标：
- 哪些功能获得资源？
- 哪些环节增加摩擦、波动、去耦？

### Layer 5 — Flow / 流向
先加入：
- 生年四化

仅当 conventions 明确支持时，再加入：
- 宫干飞化
- 自化
- 向心/离心
- 大限四化
- 流年四化
- 流月/流日/流时四化

目标：
- 资源、责任、可见度、反复成本往哪里集中？

### Layer 6 — Subsystem / 子系统抽取
根据问题调用：

身体：
- 疾厄
- 命
- 迁移
- 身宫
- 福德
- 相关煞曜和运限触发

事业：
- 官禄
- 命
- 身宫
- 财帛
- 迁移
- 交友
- 父母
- 田宅
- 子女/作品（需要时）

钱：
- 财帛
- 官禄
- 田宅
- 福德
- 迁移/交友
- 相关四化与煞曜

爱情/关系：
- 夫妻
- 福德
- 交友
- 财帛
- 子女/作品
- 兄弟
- 桃花类星曜

### Layer 7 — Time / 时间
顺序固定：

本命 → 大限 → 流年 → 小限 → 流月 → 流日 → 流时

### Layer 8 — Context / 现实门控
检查：
- 当前职业/生活环境
- 是否真的存在对应暴露条件
- 是否存在现实资源、平台、人际、身体负荷
- 是否与已知事实冲突

没有现实暴露条件时，不得把短周期信号写成具体事件。

---

## 4. 时间权限原则

强制规则：

> 时间越短，解释权限越小。

- 本命：定义长期系统结构
- 大限：改变阶段环境
- 流年：激活年度主题
- 流月：缩小年度主题窗口
- 流日：短期触发
- 流时：短时段局部聚焦

禁止：
- 流日推翻流年
- 流月重新定义本命
- 单一流时煞曜直接断重大事故
- 短周期凭空创造长期层不存在的主题

短周期有效触发条件：

1. 上层至少有一个同主题节点已激活；
2. 当前层再次击中同一宫位、同一功能链或同一四化主题；
3. 现实中存在暴露条件。

否则标记为：
`weak_short_term_signal`

---

## 5. 四化解释

ZDSM 默认将四化解释为“状态/流向变化”，不直接等同吉凶：

- 禄：增加、流入、吸引、资源化、可获得性
- 权：推动、控制、责任、占用、驱动力
- 科：整理、规范、可见、认证、缓冲
- 忌：黏着、反复、卡点、成本、难脱手

规则：

- 禄与忌可以同时成立，不得抵消。
- 四化不改变主星核心函数，只改变其运行方式或资源方向。
- “化忌”不得自动翻译为“坏事发生”。
- 必须先说：哪颗星的什么功能，在什么宫位形成何种成本。

---

## 6. 自化与飞化

自化属于 School-specific 层。

文墨天机输入若明确：
- `↓`：离心自化
- `↑`：向心自化，从对宫化入

解释原则：

- 离心：本宫功能向外释放/输出/脱离
- 向心：对宫方向的功能或压力向本宫输入

不得只写：
“某宫自化禄所以好”。

必须写完整链：
`来源/本宫 → 星曜核心函数 → 化的性质 → 目标/方向 → 现实出口`

---

## 7. 交互算子

主星、辅煞之间不做简单吉凶加减。

允许的交互类型：

1. amplification / 增强
2. support / 支援
3. buffering / 缓冲
4. disruption / 干扰
5. decoupling / 去耦
6. reconfiguration / 重构
7. gating / 门控

庙旺陷优先作为门控条件：
- 表达度
- 适配度
- 控制成本

不得用固定数值分数代替。

---

## 8. 冲突裁决

### 8.1 不平均
禁止：
- 两吉两凶 = 普通
- 禄 + 忌 = 抵消

### 8.2 分维度
若出现：
- 官禄强
- 财帛弱

输出：
- 价值生产能力强
- 价值捕获/现金流环节摩擦高

而不是“事业财运一般”。

### 8.3 优先级
结构解释优先级：

1. 主星核心函数
2. 主星组合/同宫重构
3. 庙旺陷状态
4. 三方四正
5. 高权重辅煞
6. 生年四化
7. 流派飞化/自化
8. 运限激活
9. 低权重小星/神煞

低层可以：
- 细化
- 增强
- 降低稳定性
- 改变现实出口

低层不得：
- 无条件推翻高层
- 重新定义主星本质

### 8.4 空宫
空宫：
- 允许参考对宫主星；
- 必须同时看三方；
- 不得把“借对宫”当成等同本宫坐守；
- 不使用无来源的固定百分比。

---

## 9. 置信度体系

不打“82分、73分”之类伪精确分数。

只允许：

### High / 高置信
满足：
- 本命核心结构支持；
- 至少另有 2 个独立层重复同方向；
- 或同一主题同时得到结构、四化、时间激活支持。

### Medium / 中置信
满足：
- 2 个相对独立证据；
- 或一个强结构 + 一个现实条件。

### Low / 弱提示
仅：
- 单个辅煞；
- 单个小星；
- 单一流日/流时；
- 只有一个流派特定信号。

### Reject / 不输出
- 只靠低权重小星；
- 与上层结构明显冲突；
- 需要具体事件但无现实暴露条件；
- 无法确定算法口径。

---

## 10. 结论格式

每个核心结论必须输出：

### 核心倾向
长期或当前最稳定的方向。

### 可能表现
至少 2 个现实出口；不得写单一固定剧情。

### 判断标准
告诉用户如何验证是否正在发生。

### 依据
列出：
- 宫位
- 星曜
- 庙旺
- 三方/对宫
- 四化/自化
- 时间层

### 置信度
High / Medium / Low

### 反证条件
什么现实观察出现时，需要降低这条结论的可信度。

---

## 11. 年度报告流程

### 11.1 基础盘
只放数据：
- 公历
- 农历
- 年干支
- 阴阳性别
- 命身宫
- 命宫干支
- 纳音/五行局
- 命主身主
- 十二宫星曜
- 四化
- 年支十四星
- 博士十二神
- 长生十二神
- 庙旺陷平
- 当前大限/小限/流年

禁止在基础盘提前展开完整结论。

### 11.2 年度总因果链
只在这里完整解释一次：
- 大限
- 小限
- 流年
- 年四化
- 各自三方四正
- 三层叠加后的中心节点
- 高风险节点
- 现实出口

其他章节不得重新从头推导。

### 11.3 三大主轴

身体：
- 身体底盘
- 恢复
- 行为/运动/环境暴露
- 运限触发
- 现实风险场景（仅在证据充分时）

事业：
- 工作形态
- 机会来源
- 价值生产方式
- 平台/人脉/资格
- 应沉淀的长期资产

钱：
- 能否产生价值
- 变现路径
- 现金流/交易风险
- 定价、合同、回款、分成、投入边界

爱情/关系：
- 桃花与对象来源
- 承接能力
- 伴侣类型
- 推进条件
- 风险
- 现实行为验证

### 11.4 六类关系
只写独有作用：

1. 朋友/社群/同行
2. 兄弟姐妹/同辈/团队
3. 父母/亲人/长辈
4. 爱人/伴侣
5. 合作方/客户/上级
6. 晚辈/学生/下属/粉丝/受众

每类至少回答 3 个：
- 从哪里出现
- 提供什么资源
- 消耗什么
- 分歧点
- 看什么现实行为
- 继续/降级/退出条件

### 11.5 行动清单
全文建议最后自动合并同义项。

### 11.6 年度结尾
只保留：
- 最该抓的 3 件事
- 最该避的 3 条红线
- 3 个现实验证指标

不得重新复述全文。

## 12. 去重机制

分析前先生成 `conclusion_ownership`.

每个核心结论指定唯一主章节，例如：
- 恢复不足 → 身体
- 报价/现金流 → 钱
- 作品资产化 → 事业
- 暧昧/推进 → 爱情
- 社群信息噪音 → 朋友/社群

规则：
- 年度总览只能一句话概括；
- 所属章节完整展开一次；
- 其他章节只能引用，不重复解释；
- 同一行动建议最多保留一个最完整版本。

---

## 13. 命盘辨识度检查

报告完成前必须检查：

1. 至少 3 条本盘特有高辨识度判断；
2. 每条写出“特殊组合是什么”；
3. 说明为什么不是通用模板；
4. 给现实验证方式；
5. 删除任何仅换星名仍可套给多数人的段落。

---

## 14. 具体事件预测控制

默认 `prediction_mode = trend`.

除非调用方显式设置：
`prediction_mode = specific_event`

否则禁止：
- 一定辞职
- 一定结婚
- 一定破财
- 一定遇到某人
- 某月某日必出事故

默认使用：
- 更容易
- 倾向于
- 可能表现为
- 如果现实中存在 X，则该趋势更明显

对短周期：
- 只输出“适合关注什么/容易在哪个模块产生摩擦”
- 不制造剧情

---

## 15. 身体与医疗边界

命理只能输出：
- 风险管理
- 行为模式
- 恢复与暴露条件

不得：
- 诊断疾病
- 代替检查
- 建议停药
- 用命盘否定医学意见

涉及明确症状时：
优先建议现实医学评估。

---

## 16. 验证与可反证机制

每条 High/Medium 结论应生成 validation object：

- claim_id
- analysis_window
- observable_indicators
- expected_direction
- disconfirming_observation
- evidence_trace
- confidence

周期结束后允许记录：

- observed
- partially_observed
- not_observed
- unknown

规则维护：
- 多次 not_observed → 降权/复核
- 只有事后才能解释 → 标记为 unfalsifiable，禁止作为高置信规则
- 新增小星/规则若不能提高区分度 → 删除或降为 detail-only

---

## 17. 输出模式

### professional
完整：
- 数据
- 结构
- 四化
- 三方
- 运限
- 推导链

### plain
面向命理小白：
- 人物结构
- 身体
- 事业钱
- 爱情
- 关系地图
- 行动清单
- 验证指标

plain 模式不得复制完整十二宫技术表。

---

## 18. 最终质量门

生成前检查：

- [ ] 排盘口径已锁定
- [ ] 没有混用不同四化/流月算法
- [ ] 已建立结论归属表
- [ ] 主结论不是小星主导
- [ ] 没有吉凶加减
- [ ] 没有短周期推翻长周期
- [ ] 没有单一事件必然预测
- [ ] 每条核心判断有现实验证方式
- [ ] 至少 3 条本盘辨识度结论
- [ ] 身体/事业/钱/爱情互不重复
- [ ] 六类关系只补充独有信息
- [ ] 行动建议已合并
- [ ] 结尾没有复述全文

如果任一关键项失败：
`quality_gate = fail`
并返回需要修正的项目，不直接输出最终报告。
