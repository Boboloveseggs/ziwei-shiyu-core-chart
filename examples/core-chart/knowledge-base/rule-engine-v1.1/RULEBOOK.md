# ZDSM Rulebook V1.1

## 1. 系统目标

传统命盘提供的是“宫位 + 星曜 + 状态 + 四化 + 结构关系”。
ZDSM 不直接把这些信息翻译成吉凶，而是转换成六个系统维度：

- `drive`：发动、决断、推进
- `process`：组织、处理、重构、控制
- `output`：表达、交换、向外释放
- `store`：沉淀、积累、复用
- `support`：协作、资源承接、外部支持
- `friction`：阻力、反复、冲突、消耗

每个宫最后得到一组六维向量。

## 2. 六类系统角色

| 角色 | 宫位 |
|---|---|
| engine 发动机 | 命宫 |
| processor 中央处理 | 官禄；身宫所在宫额外加权 |
| input 外部入口 | 迁移、交友、父母、兄弟、夫妻 |
| output 对外输出 | 子女、财帛 |
| storage 长期储存 | 田宅 |
| regulation/recovery 调节恢复 | 福德、疾厄 |

注意：这是 ZDSM 的功能映射，不是声称传统紫微原典把这些宫定义成同名“模块”。

## 3. 主星功能向量

`src/rules.js` 中的 `STAR_PROFILES` 给十四主星定义六维基础向量。

设计原则：

- 紫微：process 高
- 天机：process + store 高
- 太阳：output + drive 较高
- 武曲：drive 高，兼具资源管理
- 天同：support 高
- 廉贞：output/process 有力，但 friction 较高
- 天府：store/support 高
- 太阴：store/support 偏高
- 贪狼：drive/output 高，friction 较高
- 巨门：output 极高，friction 同时较高
- 天相：support/process 高
- 天梁：support 高
- 七杀：drive 极高
- 破军：process/drive 高，friction 较高

这些不是吉凶分数，是功能画像。

## 4. 庙旺陷

状态倍率：

- 庙 1.25
- 旺 1.18
- 得 1.10
- 利 1.08
- 平 1.00
- 不 0.90
- 陷 0.78

庙旺表示功能更容易稳定、明显地表达；陷不等于“坏”，只是该星功能进入更高摩擦/更高调节成本的表达状态。

在 V1.1 中，状态主要作用于主星功能强度，不直接改写摩擦值为负面剧情。

## 5. 辅曜与煞曜

辅曜负责补资源、组织、支持、结构化；
煞曜主要增加 friction，部分也提升 drive/output。

规则表见 `AUX_PROFILES`、`MALEFIC_PROFILES`。

## 6. 四化

四化统一作为“流量/方向”修正：

- 禄：增加 output + store
- 权：增加 drive + process
- 科：增加 process + store
- 忌：增加 friction，同时略提高 output（代表事情被持续处理、反复显化）
- 离心自化：额外增加 output
- 向心自化：额外增加 process

注意：
- 四化表本身存在门派差异，本引擎只接受已经排好的四化落点，不负责决定哪一年哪颗星化什么。
- 排盘软件负责“算四化”，本引擎负责“解释结构”。

## 7. 身宫

若某宫 `body: true`：

- drive +0.8
- process +0.9
- 系统角色优先提升为 processor 候选

含义：实际长期资源投入和后天行为更集中于该宫。

## 8. 三方四正

V1.1 加入固定传统宫位组：

- 命—财—官，命对迁
- 兄—田—疾
- 夫妻—福德—迁移
- 子女—父母—交友

三方四正只做“结构耦合加成”：

- 同组三合：双方 strength 增加小幅 structuralBonus
- 对宫：增加较小的 couplingBonus
- 不直接复制对宫主星，不使用固定“借七成”规则

## 9. 系统识别

### 发动机
优先取命宫。

### 中央处理器
候选为：
- 官禄宫
- 身宫所在宫

取 `process` 最高者。

### 主要入口
从迁移、交友、父母、兄弟、夫妻中按 `support + process*0.25 - friction*0.12` 排序，取前 2–3 个。

### 主要输出
子女、财帛按 `output - friction*0.10` 排序。

### 长期积累
优先田宅；若田宅极弱，再允许全盘 `store` 最高节点替代。

### 最大瓶颈
按：
`friction + strength*0.15`
排序。

### 恢复节点
只在福德、疾厄中比较：
`strength + friction*0.25`

## 10. 主增长循环

标准骨架：

`发动机 → 中央处理器 → 主要输出 → 长期积累 → 中央处理器`

例：
`命 → 官 → 子女 → 田宅 → 官`

如果财帛明显强于子女，则可生成：
`命 → 官 → 财 → 田 → 官`

如果两个输出接近，则主图保留双分支。

## 11. 恢复循环

标准骨架：

`中央处理器 → 福德 → 疾厄 → 发动机 → 中央处理器`

这里表达的是“工作/任务 → 精神负荷 → 身体恢复 → 行动能力”的系统反馈，不是医学诊断。

## 12. 图表裁剪

主图目标是“看懂”，不是“完整”。

默认：
- 最多 3 个入口
- 最多 2 个输出
- 1 个积累节点
- 1 个恢复节点
- 1 个发动机
- 1 个处理中枢

同名节点自动合并。

次要关系不进入主图，但保留在 engine 输出 JSON 的 `hiddenEdges`。

## 13. 动画

动画不是随机移动。
每条边的粒子严格从 `source → target` 运动。

默认只动画：
- 主增长循环
- 恢复循环
- 主要入口 → 中枢

这样避免视觉噪音。

## 14. 运限扩展接口

输入可选：

```json
"timing": {
  "decade": {"palace":"福德"},
  "year": {"palace":"子女"},
  "smallLimit": {"palace":"交友"},
  "transforms": [...]
}
```

V1.1 的实现原则：

- 本命分数先算完并锁定
- 运限只生成 `activationBonus`
- 动态层不得改写本命角色，只改变“今年哪些节点更亮”
- 图上通过 halo/高亮显示，不新增一套重复结构

## 15. 禁止事项

- 不把某星直接翻译成固定事件。
- 不给出“必然发生”。
- 不把权重称为科学概率。
- 不因为化忌就自动判凶。
- 不因为庙旺就自动判吉。
- 不把所有三方四正都画出来。
- 不把所有辅星都变成节点。
