# 给网站开发 AI 的安装说明（P5 月运补充包）

## 目标

把 P5 合并进现有 ZDSM P4 网站。

**不要新增任何 AI/LLM API。**
月运报告由本地规则引擎生成。
报告底部继续使用 P4 的人工联系方式。

---

## 1. 复制文件

把本补充包中的：

```text
engine/monthly_runtime.py
engine/render_monthly_dashboard.py
schemas/monthly_request.schema.json
schemas/monthly_output.schema.json
data/monthly_runtime_config.json
viewer/
```

复制进 P4 对应目录。

不得删除 P4 的：
- 本命规则库
- 星×宫规则
- 庙旺
- 四化配置
- 报告编译器
- `config/contact.json`

---

## 2. 新增网站入口

建议导航：

```text
现在
今年
本月   ← 默认高频入口
今天
完整命盘
```

新增页面：

```text
/monthly
/monthly/{yyyy-mm}
```

---

## 3. 月运输入

排盘器必须先提供：

- 当前大限落宫
- 当前流年落宫
- 当前小限落宫（可选但建议）
- 当前流月命宫
- 流月四化及目标宫

P5 **不负责猜流月算法**。

如果网站的排盘引擎尚未实现流月：
前端显示：

> 当前排盘模块尚未提供本月流月位置，无法生成月运。

不得调用 AI 猜。

---

## 4. 调用方式

后端调用：

```bash
python engine/monthly_runtime.py   chart.json   monthly_request.json
```

返回 JSON 后保存为：

```text
monthly_output.json
```

如果使用现成 HTML Renderer：

```bash
python engine/render_monthly_dashboard.py   monthly_output.json   config/contact.json   monthly.html
```

也可以由现有前端直接读取 `monthly_output.json` 自己渲染。

## 6. 重要解释规则

必须保留：

> 本命定结构  
> 大限定十年背景  
> 流年定年度任务  
> 小限定个人响应辅助  
> 流月定本月焦点  
> 流月三方四正定本月事件系统

禁止：

- 只看流月命宫就断事件
- 流月推翻大限/流年
- 红鸾单独断恋爱
- 病符单独断疾病
- 忌单独断破财
- 用星曜数量做吉凶总分

## 8. AI 开发者验收标准

完成后必须验证：

1. 页面生成过程中无 OpenAI/Gemini/Claude 等 API 请求。
2. 没有流月数据时明确报错，不猜。
3. 不同 `monthly.palace` 会生成不同三方四正网络。
4. 月忌优先参与瓶颈识别，但不自动翻译成灾祸。
5. 月禄/科/权优先参与机会节点识别。
6. 共振必须来自至少两个独立层，不能把同一条规则重复算多次。
7. 小限只能辅助，不可覆盖流年。
8. 四大现实轴允许出现“低”，不强行凑篇幅。
9. 页面底部只有人工联系方式，没有 AI 入口。
10. 完整命盘 P4 功能继续可用。
